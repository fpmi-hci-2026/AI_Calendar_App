# Шпаргалка — «Умный Календарь»

---

## 1. Что такое приложение и зачем оно нужно

**Умный Календарь** — веб-приложение для личного планирования: создаёшь события (встречи, задачи, заметки), смотришь их в режиме месяца или недели, ведёшь заметки и видишь аналитику своей активности.

Всё хранится на сервере и привязано к аккаунту пользователя — зашёл с любого устройства, данные твои.

---

## 2. Архитектура — три уровня

```
Браузер / телефон
      ↕  HTTP + JSON
  Next.js (порт 3000)   ← фронтенд, то что видит пользователь
      ↕  REST API
  FastAPI  (порт 8000)  ← бэкенд, бизнес-логика
      ↕  SQL
  PostgreSQL             ← база данных, хранилище
```

**Ключевой принцип:** фронтенд и бэкенд — полностью независимые программы. Они не знают ничего друг о друге кроме того, какие HTTP-запросы отправлять и что получать в ответ.

## 3. Технологии — зачем каждая

### Фронтенд
| Технология | Зачем |
|---|---|
| **Next.js 14** | Фреймворк для React. App Router — каждая папка в `/app` — отдельная страница. Умеет рендерить на сервере (SSR) и в браузере (CSR). |
| **TypeScript** | JavaScript со строгой типизацией. Если ожидаешь `string`, а пришёл `number` — ошибка ещё при написании кода, не в браузере. |
| **Tailwind CSS** | Стили прямо в HTML через классы (`text-sm`, `rounded-xl`, `bg-emerald-500`). Не пишешь отдельные CSS-файлы. |
| **Recharts** | Готовые графики для React: `BarChart` (столбики), `PieChart` (круговая диаграмма). |

### Бэкенд
| Технология | Зачем |
|---|---|
| **FastAPI** | Фреймворк для Python. Автоматически генерирует документацию на `/docs` — можно тестировать API прямо в браузере. |
| **SQLAlchemy** | ORM — пишешь Python-классы, они превращаются в таблицы БД. Не нужно писать SQL вручную. |
| **Alembic** | Миграции БД — управление изменениями схемы (добавил поле → создал миграцию → применил). |
| **python-jose** | Создаёт и проверяет JWT-токены. |
| **passlib + bcrypt** | Хэширует пароли. bcrypt — медленный алгоритм специально для паролей (защита от перебора). |

## 4. Авторизация — как работает JWT

**JWT (JSON Web Token)** — строка из трёх частей: `заголовок.данные.подпись`

Данные (payload) содержат `user_id` и срок действия. Подпись сделана секретным ключом сервера — нельзя подделать.

### Схема входа:
```
1. POST /api/auth/login  { email, password }
2. Сервер: bcrypt.verify(password, hash_из_БД)
3. Сервер выдаёт:
   • access_token  — живёт 30 минут (для запросов)
   • refresh_token — живёт 7 дней  (для обновления access)
4. Фронтенд сохраняет оба в localStorage
5. Любой запрос к API:  Authorization: Bearer <access_token>
6. Если access истёк → 401 → POST /api/auth/refresh → новый access
7. Если refresh тоже истёк → logout, redirect на /auth
```

### Почему два токена?
- Access короткий — если украли, через 30 мин уже бесполезен
- Refresh длинный — чтобы не вводить пароль каждые 30 минут
- Refresh обновляет access без участия пользователя

### В коде (api.ts):
```typescript
// При каждом запросе автоматически добавляется токен
headers: { Authorization: `Bearer ${tokens.getAccess()}` }

// При 401 — автообновление
if (res.status === 401 && retry) {
  const refreshed = await tryRefresh();
  if (refreshed) return request(path, options, false); // повтор
  tokens.clear();
  window.location.href = '/auth'; // logout
}
```

## 5. База данных — модель данных

**4 таблицы, связанные через внешние ключи:**

```
users
  id | email | name | hashed_password | created_at

events
  id | user_id → users.id | title | description
     | date | start_time | end_time
     | type: meeting/task/note | link | created_at

notes
  id | user_id → users.id | title | text | date | created_at

notifications
  id | user_id → users.id | event_id → events.id
     | message | is_read | send_at
```

**Каскадное удаление:** `cascade="all, delete-orphan"` — удалил пользователя, удалились все его данные автоматически.

**Как SQLAlchemy описывает таблицу (пример Event):**
```python
class Event(Base):
    __tablename__ = "events"
    id      = Column(Integer, primary_key=True)
    user_id = Column(Integer, ForeignKey("users.id", ondelete="CASCADE"))
    title   = Column(String(512), nullable=False)
    date    = Column(Date, nullable=False)
    type    = Column(Enum("meeting", "task", "note"), nullable=False)
    # ...
    owner   = relationship("User", back_populates="events")
```

**Pydantic — схемы для валидации запросов/ответов:**
```python
class EventCreate(BaseModel):
    title: str
    date: date
    type: Literal["meeting", "task", "note"]

class EventOut(BaseModel):
    id: int
    user_id: int
    title: str
    model_config = {"from_attributes": True}  # читает из ORM-объекта
```

## 6. REST API — структура эндпоинтов

**REST** = каждый URL — ресурс, HTTP-метод — действие.

| Метод | URL | Действие |
|---|---|---|
| POST | /api/auth/register | Регистрация |
| POST | /api/auth/login | Вход |
| POST | /api/auth/refresh | Обновить токен |
| GET  | /api/auth/me | Текущий пользователь |
| GET  | /api/events?from_date=&to_date= | Список событий за период |
| POST | /api/events | Создать событие |
| PUT  | /api/events/{id} | Обновить событие |
| DELETE | /api/events/{id} | Удалить событие |
| GET/POST/PUT/DELETE | /api/notes | Заметки |
| GET  | /api/analytics?from=&to= | Статистика |

**Защита — зависимость FastAPI:**
```python
@router.get("/events")
def get_events(current_user: User = Depends(get_current_user)):
    # Только если токен валидный — иначе 401
    return db.query(Event).filter(Event.user_id == current_user.id).all()
```

**Перекрёстный доступ блокируется:**
```python
def _get_event_or_404(event_id, user, db):
    event = db.get(Event, event_id)
    if not event or event.user_id != user.id:
        raise HTTPException(404)  # чужое событие — 404, не 403
```

## 7. Фронтенд — как устроено

### App Router (Next.js 14)
```
/src/app/
  auth/page.tsx       → страница /auth
  dashboard/page.tsx  → страница /dashboard
  notes/page.tsx      → страница /notes
  analytics/page.tsx  → страница /analytics
```

### 'use client' — зачем эта директива?
Next.js по умолчанию рендерит на сервере. Но сервер не знает о `localStorage`, `window`, обработчиках событий. `'use client'` говорит: «эту страницу рендерить в браузере».

Все наши страницы начинаются с `'use client'` — потому что работают с токенами и пользовательскими действиями.

### Маппер snake_case → camelCase (api.ts)
Бэкенд (Python) использует `snake_case`: `user_id`, `start_time`.  
Фронтенд (TypeScript) ожидает `camelCase`: `userId`, `startTime`.

Решение — функция-маппер:
```typescript
function mapEvent(e: Record<string, unknown>): CalendarEvent {
  return {
    id:        e.id          as number,
    userId:    e.user_id     as number,    // snake → camel
    startTime: (e.start_time as string)?.slice(0, 5), // "10:30:00" → "10:30"
    // ...
  };
}
```

### Компоненты календаря
- **MonthView** — сетка 7×N ячеек. Для каждой ячейки проверяет, есть ли события на эту дату → рисует цветные точки.
- **WeekView** — 7 строк (пн–вс). В каждой строке список событий того дня с типом и временем.
- **EventForm** — модальное окно с формой. `useEffect` заполняет поля при редактировании существующего события.

## 9. Аналитика — как считается

**Бэкенд** (`/api/analytics?from=&to=`):
```python
# Всего событий
total = db.query(func.count(Event.id)).filter(
    Event.user_id == user.id,
    Event.date >= from_date,
    Event.date <= to_date
).scalar()

# По типам
by_type = db.query(Event.type, func.count()).group_by(Event.type).all()

# По дням
daily = db.query(Event.date, func.count()).group_by(Event.date).all()
```

**Фронтенд** берёт `daily_activity: [{date, count}]` и строит bar-chart через Recharts:
```tsx
<BarChart data={barData}>
  <Bar dataKey="События" fill="#10b981" radius={[4,4,0,0]} />
</BarChart>
```

Pie-chart — из `by_type: [{type, count}]`, каждый тип — свой цвет (emerald/blue/amber).

## 10. Docker — что и зачем

`docker-compose.yml` запускает три сервиса одной командой:

```
postgres  — PostgreSQL в контейнере (данные в volume postgres_data)
backend   — FastAPI, собирается из Dockerfile, hot-reload через volume
```

Фронтенд запускается отдельно (`npm run dev`) — так быстрее при разработке.

**Команды:**
```bash
docker compose up --build    # первый запуск, собирает образы
docker compose up            # обычный запуск
docker compose down          # остановить
docker compose exec backend alembic upgrade head  # применить миграции
```

**Почему `depends_on` с healthcheck важен:**  
Без него бэкенд стартует раньше PostgreSQL и падает с ошибкой подключения. `healthcheck` заставляет ждать пока `pg_isready` не ответит успехом.

## 11. Возможные вопросы на защите

**— Почему Next.js, а не чистый React?**  
Next.js добавляет роутинг из коробки, оптимизацию изображений, возможность SSR. Не нужно настраивать Webpack и react-router вручную.

**— Зачем хранить токены в localStorage, а не cookies?**  
localStorage проще в реализации. Для учебного проекта достаточно. В продакшне cookies с `httpOnly` безопаснее (защита от XSS), но требуют CSRF-защиты.

**— Что такое ORM и зачем он нужен?**  
ORM (Object-Relational Mapping) — слой между кодом и БД. Пишешь Python-объекты, ORM переводит в SQL. Плюсы: меньше SQL вручную, защита от SQL-инъекций, проще менять БД.

**— Как защищены данные пользователей?**  
Пароли хэшируются bcrypt (односторонний хэш, нельзя расшифровать). Каждый запрос к API проверяет токен. Нельзя получить чужие данные — запросы фильтруются по `user_id` из токена.

**— Зачем Alembic если SQLAlchemy может создавать таблицы сам?**  
`Base.metadata.create_all()` создаёт таблицы, но не умеет их менять. Alembic генерирует SQL-скрипты изменений (добавить колонку, переименовать) и хранит историю — можно откатиться.

**— Что такое CORS?**  
Cross-Origin Resource Sharing — браузер запрещает запросы с `localhost:3000` на `localhost:8000` если сервер явно не разрешил. В FastAPI: `CORSMiddleware(allow_origins=["*"])` — разрешаем все источники (для разработки).

**— Как работает каскадное удаление?**  
В SQLAlchemy: `ForeignKey("users.id", ondelete="CASCADE")` — на уровне БД. При `DELETE FROM users WHERE id=X` PostgreSQL автоматически удаляет все строки из events/notes где `user_id=X`.
