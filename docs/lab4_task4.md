### Задание 4. Проектирование и тестирование API

**Цель —** реализовать запросы и выполнить их тестирование с помощью Mock-сервера.

#### 4.1. Разработка спецификации OpenAPI

Разработка API велась с использованием веб-фреймворка FastAPI (Python). Одним из главных преимуществ данного фреймворка является автоматическая генерация спецификации OpenAPI 3.0 (Swagger) на основе описанных моделей Pydantic и маршрутов.

Для выполнения требований лабораторной работы спецификация была выгружена и импортирована в сервис **SwaggerHub** для внешнего документирования, валидации и создания Mock-сервера. Спецификация описывает следующие основные группы маршрутов:

- `/api/auth/*` — регистрация и аутентификация (выдача JWT).
    
- `/api/events/*` — CRUD-операции для событий календаря.
    
- `/api/notes/*` — управление заметками.
    
- `/api/ai/*` — взаимодействие с AI-ассистентом.
    
- `/api/analytics/*` — получение статистики загруженности.

#### 4.2. Тестирование с использованием Mock-сервера

В SwaggerHub был активирован модуль **API Auto Mocking**. Mock-сервер позволяет симулировать ответы API на основе разработанной спецификации без необходимости подключения реальной базы данных, что ускоряет процесс разработки клиентской части.

В ходе тестирования Mock-сервера были проверены следующие сценарии:

1. **Создание события (`POST /api/events/`)**. Отправлено тело запроса в формате JSON с данными о событии (заголовок, дата, время начала и окончания). Mock-сервер вернул статус **201 Created** и сгенерированный JSON-объект события с присвоенным идентификатором.
    
2. **Получение списка событий (`GET /api/events/`)**. При отправке запроса без параметров Mock-сервер вернул статус **200 OK** и массив тестовых данных.

#### 4.3. Локальное тестирование API (Swagger UI)

Помимо тестирования Mock-сервера, API было развернуто локально с использованием Docker-контейнеров (через `docker-compose`). FastAPI автоматически предоставляет интерактивную документацию Swagger UI по адресу `http://localhost:8000/docs`, где можно отправлять реальные запросы к базе данных PostgreSQL.

Была проведена проверка системы безопасности (JWT-аутентификации). При попытке вызвать защищенный эндпоинт без токена сервер корректно возвращает ошибку **403 Forbidden**.

Для успешного выполнения запроса был использован следующий алгоритм:

1. Выполнен вход через эндпоинт `/api/auth/login` для получения JWT-токена.
    
2. Токен вставлен в окно авторизации Swagger UI (кнопка Authorize).
    
3. Выполнен запрос на создание нового события (`POST /api/events/`), который вернул статус **201 Created**.
